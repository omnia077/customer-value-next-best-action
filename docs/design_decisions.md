# Design decisions

Why the project is built the way it is, including where it differs from the original working spec.

## Method decisions

| Item | Decision | Why |
|---|---|---|
| Segments | k = 4 (k = 3 was more stable: ARI 0.95 vs 0.89) | k = 4 separates a very low-value group (4.8% of revenue) from a lapsing data-led group (10.7%), which need different actions. k was **not** chosen on the recovery score |
| GMM | Tried in an early run (BIC unreliable for k >= 6); not in the final module | Adds nothing over k-means here |
| Population | Prepaid subscribers active in the last 90 days | Without the rule, 11% of lines had already churned and skewed two segments; conclusions otherwise similar (`outputs/k_selection_*.csv`) |
| CLV library | Own BG/NBD + Gamma-Gamma (`src/clv.py`) | `lifetimes` is unmaintained and fragile with pandas 3. The formula was checked against Monte Carlo simulation (92-day expectation 6.086 vs 6.086); the fitted a = 0.07 (< 1) is valid |
| Uplift learners | 5 compared, chosen by 5-fold cross-validation on April only | A fixed T-learner had rank correlation +0.39 (10-seed mean); the CV-selected learner +0.56. June was never used to choose |
| Propensity features | Segment ID is **not** used | Segments are fit as of 30 Sep; using them at earlier cutoffs would leak the future |
| Win-back value | Weighted by (1 - p_alive) | The first version priced every lapsed line as truly gone and over-allocated budget |
| Churn input | Stand-in in committed results; Project 1 compared separately | Real scores need the salt and cannot be regenerated by CI (see `project1_integration.md`) |
| Airflow | DAG written, **not executed** | Airflow is not installed here; the same steps run and are tested through `score_monthly.py` |
| Model registry | Not used; metrics and artifacts go to MLflow (sqlite) | Scores come from the run that trains the models |
| Billing DWH | KPI definitions (ARPU, MOU) mirrored in DuckDB; `dim_segment` and `fact_customer_value` ready for its Gold layer | The DWH holds a different population and no recharge events. Regenerating it with shared customers was considered and not recommended |
| IDs | `customer_id` everywhere; hashing helper matches Project 1's scheme | No MSISDN reaches any output |

## Governance

- Segments and CLV are commercially sensitive: restrict access by role.
- `age`, `gender`, region and MSISDN are not model inputs. `outputs/fairness_audit.csv` shows contact rates by age band (27.2-31.5%) and region (27.7-33.0%).
- One action per subscriber per period (`test_actions_one_per_subscriber_and_budget`).
- Document the retention period and permitted use of campaign data before any real use.
- Only surrogate IDs appear in committed files; the real hashing salt is never stored in the repository.
